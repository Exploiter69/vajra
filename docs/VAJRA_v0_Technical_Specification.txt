VAJRA v0 — Technical Specification
Status: Phase 5 — Architecture Specification
Project: VAJRA
Purpose: Durable autonomous engineering runtime
Implementation status: Not yet implemented
Primary constraint: ₹0.00 operating cost




1. System Definition
VAJRA is a durable autonomous engineering runtime that accepts an engineering objective and attempts to
produce a verified engineering artifact.


VAJRA is not:


     • a chatbot
     • an LLM wrapper
     • an IDE
     • a single autonomous agent
     • a Telegram bot
     • a model hosting platform
     • a collection of shell scripts

VAJRA is a durable execution system for engineering work.


Its fundamental guarantee is:


       A worker, model, process, network connection, or machine may disappear without destroying
       the Engineering Run.


The system must maintain canonical state independently from the model and workers.




2. Architectural Laws
These laws are normative.


Law 1 — Model Is Not Authority
A model may propose actions.


A model may never directly authorize or execute them.



                                                   1
  Model
    ↓
  Intent
    ↓
  Policy
    ↓
  Execution Broker
    ↓
  Actual operation




Law 2 — VAJRA Owns Canonical State
Models, workers, Telegram, files, caches and external services are not authoritative state stores.


VAJRA's durable state is authoritative.




Law 3 — Meaningful Operations Are Durable
A meaningful engineering operation must have a durable representation.


Examples:


      • planning
      • model invocation
      • patch application
      • command execution
      • verification
      • human approval
      • worker assignment
      • retry
      • recovery




Law 4 — Reasoning Cannot Directly Execute
The reasoning plane can produce structured intents.


It cannot directly call arbitrary shell commands, manipulate Git, access credentials, or modify the repository.




                                                      2
Law 5 — Worktree Isolation Is Not Security Isolation
Git worktrees provide logical repository isolation.


They do not provide:


     • kernel isolation
     • network isolation
     • credential isolation
     • process isolation
     • filesystem security

Those responsibilities belong to the execution environment.




Law 6 — Verification Is External
A model saying:


       "The task is complete."


is not evidence of completion.


Completion requires independently generated evidence.




Law 7 — Failure Is Data
Failures must be represented explicitly.


A failed attempt is not the same thing as a failed Engineering Run.




Law 8 — Autonomy Is Bounded
Every autonomous Run must have limits.


At minimum:


     • time budget
     • step budget
     • retry budget
     • execution budget
     • model budget
     • resource limits




                                                      3
         • scope limits

There is no infinite retry loop.




Law 9 — Progress Requires Evidence
VAJRA must distinguish:



  model believes progress happened


from:



  verified artifact exists


Only the latter constitutes engineering progress.




Law 10 — Human Is Ultimate Authority
VAJRA may operate autonomously within explicitly granted policy.


Certain actions must transition the Run into durable:



  WAITING_HUMAN


state.

Primary lifecycle:



  CREATED
     ↓
  QUEUED
     ↓
  ORIENTING
     ↓
  PLANNING
     ↓
  EXECUTING
     ↓
  VERIFYING
     ↓
  CANDIDATE
     ↓
  PROMOTION
     ↓
  COMPLETE


Exceptional states:




                          8
  RECOVERING
  PAUSED
  WAITING_HUMAN
  FAILED
  ABORTED
  EXPIRED



State rules

CREATED

Run exists but has not entered execution.


QUEUED

Run is waiting for scheduling.


ORIENTING

Repository/context discovery.


PLANNING

Model produces structured engineering plan/intents.


EXECUTING

Approved operations are performed.


VERIFYING

Independent verification is running.


CANDIDATE

Evidence indicates the requested outcome may have been achieved.


PROMOTION

Final policy-controlled promotion is occurring.


COMPLETE

Acceptance criteria have been satisfied and final disposition recorded.




                                                      9
RECOVERING

VAJRA is reconciling state after failure.


WAITING_HUMAN

Run requires human authorization.


FAILED

Run cannot continue under its current policy/budget.


ABORTED

Human/system explicitly stopped the Run.


EXPIRED

Run exceeded its allowed lifetime.

9. Durable Runtime
Candidate

candidate.


VAJRA must not expose Restate-specific semantics throughout the application.


Instead:



  VAJRA
    ↓
  DurableRuntime interface
    ↓
  Restate adapter


This preserves the ability to evaluate alternatives later.

22. Memory
VAJRA v0 intentionally does not begin with a vector database.


Initial persistent memory consists of:


      • Run history
      • events
      • artifacts
      • verification evidence
      • failure history
      • structured decisions
      • relevant repository state

Principle:


       History first. Memory later.


This reduces memory poisoning and unnecessary complexity.

26. No-Progress Detection
VAJRA must detect cases where repeated attempts produce no meaningful advancement.


Examples:



  same patch repeatedly proposed
  same test repeatedly fails
  same error repeated
  repository unchanged across attempts
  model oscillates between strategies


A Run must eventually stop or escalate rather than loop indefinitely.

28. Checkpoint Model
A checkpoint records enough state to support recovery.


Conceptually:



  Checkpoint
  ├── checkpoint_id
  ├── run_id
  ├── step_id
  ├── event_position
  ├── git_revision
  ├── workspace_identity
  ├── policy_version
  ├── state_digest
  └── evidence_refs


Git stash alone is insufficient as a complete checkpoint mechanism because untracked files and external
state can escape it.


Checkpoint semantics therefore belong to VAJRA rather than being delegated entirely to Git.




29. Recovery
Recovery must reconcile actual state with durable state.



  worker/process dies
          ↓
  durable runtime detects interruption
          ↓
  Run enters RECOVERING
          ↓
  reconcile:
    - current Run state
    - event history




                                                     25
    - workspace
    - Git state
    - checkpoint
    - worker lease
          ↓
  resume / retry / rollback / human


VAJRA must not blindly assume the external world matches its previous state.




30. Security Boundary
VAJRA treats the following as untrusted:


     • model output
     • repository contents
     • repository instructions
     • dependencies
     • generated scripts
     • worker environment
     • external tools
     • network responses
     • persisted model-generated memory

Threat classes include:


     • prompt injection
     • tool injection
     • command injection
     • path traversal
     • symlink attacks
     • credential exposure
     • dependency attacks
     • network exfiltration
     • sandbox escape
     • verification manipulation
     • memory poisoning
     • stale-worker execution




31. Credentials
Secrets must not be placed directly into normal model context.




                                                    26
